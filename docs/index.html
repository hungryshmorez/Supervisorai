How it works

Five stages, one closed loop. The supervisor never declares success until every dependency verifies.

STEP 1 · PLAN

MiniMax-M3 decomposes the goal into a validated task DAG with explicit dependencies, and assigns each task the best specialist from the roster.

STEP 2 · DELEGATE

Each ready task is dispatched to an M3-backed worker running with its persona as a system prompt — coder.python, reviewer.code, and more.

STEP 3 · AUDIT

The supervisor verifies each output against the plan: an M3 audit verdict, a heuristic quality analyzer, an LLM second-opinion judge, and a drift check.

STEP 4 · CORRECT

Failed or drifted outputs are re-prompted with a concrete correction hint and re-audited — the loop self-heals instead of shipping a broken step.

STEP 5 · SYNTHESIS

Only when every dependency passes does the system synthesize a final, verified result — here, a PR summary suitable for human review.

🛡️ HITL GATE

Tasks marked high_stakes halt for explicit human approval before a shippable artifact is written. Never auto-approved.
